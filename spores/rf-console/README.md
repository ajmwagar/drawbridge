# RF Deck — RF console prototype

A multi-radio console: receiver rail, spectrum, waterfall, tuning,
demodulation controls, presets, signal meter, and capture state.

The receiver UI and spectrum are simulated and labelled `SIMULATED SPECTRUM`.
The band map can use a live TinySA presence service; when the service is not
available it falls back to a checked-in `SNAPSHOT`. No SDR is opened by the
browser, and the TinySA is owned by the native scout sidecar.

## Source shape

Most of the page is Soil now:

```text
source/data.soil     receivers, signals, initial events
source/bandmap.soil  24 band-map places, categories, regional copy, GPS state
source/ui.soil       HTML shell, rail, scope, inspector, controls
tests/render.soil    pure page/data/escape checks
web/rf-console.js    canvas spectrum + waterfall and in-place DOM updates
web/rf-console.css   design tokens and layout
web/index.html       generated by Soil; do not hand-edit
web/scout.json       last-known tinySA4 presence snapshot
tools/export.sh      render source into the page
tools/scout.py       one-shot scan that rewrites scout.json
tools/scoutd.py      live tinySA presence service (HTTP JSON)
tools/scout_core.py  shared serial scan logic
```

The browser script no longer defines the receiver inventory or controls. It
reads the Soil-generated `#rf-state` JSON, draws the canvases, and updates the
rendered DOM. The band map is Soil data: 24 named places grouped as Weather,
Emergency, Satellites, Data & LoRa, Aviation, Marine, Broadcast, and Amateur.
Cards carry the recommended radio, antenna, and a `Scout` reading. The page
polls `https://rfscout.myc/scout.json`; when that service is unavailable it
falls back to `web/scout.json` and labels the reading `SNAPSHOT`.

## Preview

- **Genre:** atmospheric
- **Macrostructure:** instrument console — rail / scope / inspector, not a
  marketing page
- **Theme:** field monitor — ink-green panels, bone text, amber carrier,
  cyan trace
- **Typography:** SF Mono / Cascadia / ui-monospace for data; Avenir Next /
  system sans for supporting copy
- **Slop test:** pass
- **Key decisions:** one receiver selection model for SDR, packet, and
  broadcast devices; draggable tuning; canvas waterfall; mock data explicitly
  marked; no fake browser chrome, invented metrics, or rounded card grid

## Rebuild the page

```sh
./tools/export.sh
```

This runs the Soil interpreter over `source/data.soil`, `source/bandmap.soil`,
and `source/ui.soil`, then writes `web/index.html`.

Run the pure checks with:

```sh
./tests/run.sh
```

## Live scout

`tools/scoutd.py` is the native sidecar for the USB device. It owns the serial
session, scans every preset in a loop, and serves the latest cache as JSON:

```text
GET http://127.0.0.1:8798/scout.json
GET http://127.0.0.1:8798/healthz
```

The Soil page polls `https://rfscout.myc/scout.json` every 15 seconds and
updates the band cards in place. It never opens serial and never blocks the
page on the device. If the service is down, the page falls back to
`web/scout.json` and says `SNAPSHOT`; if the service has a previous complete
pass, it keeps those readings but marks them `STALE`.

### macOS

The TinySA must be plugged into the machine running the service.

```sh
./tools/install-scoutd-macos.sh
curl -s http://127.0.0.1:8798/healthz
```

This installs a LaunchAgent and keeps the service alive across login. The
frontdoor route is:

```json
{
  "name": "rfscout",
  "hosts": ["rfscout.myc"],
  "upstream": "http://127.0.0.1:8798",
  "service_kind": "rf-scout"
}
```

### Linux / Pi

Run the same service as the radio user, with the serial device explicit:

```sh
sudo -u radioman ./tools/scoutd.py --listen 0.0.0.0:8798 --port /dev/ttyACM1 --antenna AR-771
```

The current deployment is on `radioman-pi` at `192.168.2.90`:

```text
/opt/rf-console/scoutd.py
/opt/rf-console/scout_core.py
/opt/rf-console/index.html
```

The systemd unit is `/etc/systemd/system/rfscoutd.service` and the frontdoor
upstream is:

```json
"upstream": "http://192.168.2.90:8798"
```

The service is deliberately not bound to the public interface. The Mac
frontdoor proxies `rfscout.myc` to the Pi over the LAN. `tools/rfscoutd.service.example`
is the same service as a unit; adjust paths and serial device for another host.

The service returns `status: "offline"` with a readable `error` while the
device is absent, so the UI can distinguish a dead device from an old scan.
A complete pass flips it to `status: "live"`; partial passes do not, because a
band map with only two fresh cards would be misleading.

### One-shot snapshot

`tools/scout.py` remains useful for a checked-in fallback or for testing the
radio:

```sh
./tools/scout.py --port /dev/ttyACM1 --antenna AR-771
```

It writes `web/scout.json` with the same reading shape the live service uses.

### Band map model

The page opens a big `Pick a band` sheet from the scope toolbar. It starts as a
folder grid: Weather, Emergency, Satellites, Data & LoRa, Aviation, Marine,
Broadcast, and Amateur. Selecting a folder shows its band cards, with an
`All bands / Weather` breadcrumb back to the folder grid. Each card carries a
plain-language `copy` and a `hear` line: what the signal should sound like, not
just a frequency.

`source/bandmap.soil` also carries regional tags (`us`, `europe`, `global`) and
a GPS placeholder:

```lisp
(defun rf/gps ()
  (list (list :fix #f)
        (list :source "MeshCore GPS")
        (list :region "us")
        (list :label "US / Pacific NW")
        ...))
```

No fix means the region selector falls back to the last known region. A real
MeshCore GPS position can replace this without changing the page shape.

## Run the UI

```sh
python3 -m http.server 8099 --directory web
# open http://127.0.0.1:8099
```

The Spore claims `drawbridge` as its Mycelium service name. Mycelium service
names are single DNS labels; a dotted public host is a frontdoor alias. This is
the route used locally:

```json
{
  "name": "drawbridge",
  "hosts": ["drawbridge.dev.myc"],
  "upstream": "http://127.0.0.1:8799",
  "service_kind": "rf-console",
  "priority": 20
}
```

With that route, `https://drawbridge.dev.myc/` serves the web surface.

Or install the package into a Loam root once web surfaces are enabled:

```sh
loam install . --root ~/.mycelium/spores
loamd serve --web-listen 127.0.0.1:8799 --root ~/.mycelium/spores
```

## Direction

The eventual data plane should stay outside the Spore:

```text
Spore web surface  -> control capability -> native radio host
browser / wry      -> loopback FFT + PCM  -> native radio host
```

The Spore owns layout, policy, presets, and acknowledgement ordering. The
native host owns devices, tuning locks, DSP, recordings, credentials, and the
high-rate transport. This prototype is the UI shell that will sit on top of
that boundary.

## Interactions

- Click a receiver to switch devices.
- Drag the spectrum or use the mouse wheel to tune.
- Arrow keys nudge; space starts/stops RX.
- Presets switch device and tuning.
- Mode, bandwidth, gain, squelch, peak hold, and record controls are live.
